# Better Data 系统架构

## 总览

Better Data 采用 Windows 本地优先架构：桌面启动器负责生命周期和系统托盘，浏览器前端负责交互，本地 FastAPI 后端负责文件、项目、任务和数据处理，工作进程负责高成本计算。

```text
Windows 启动器
  ├─ 系统托盘与本地通知
  ├─ 启动 127.0.0.1 本地服务
  └─ 打开默认浏览器
             │
React 工作台 ─┼─ FastAPI API
             │     ├─ 项目服务
             │     ├─ 数据画像与规则引擎
             │     ├─ 流水线编排器
             │     ├─ 任务队列与检查点
             │     └─ 报告与导出
             │
             └─ SQLite 元数据 + Parquet 工作数据 + 原始文件副本
```

## 组件边界

- 前端：八阶段工作流、字段配置、问题证据、流水线编辑、任务进度和导出。
- API：本地令牌校验、输入验证、项目和任务状态接口，不在请求线程执行大计算。
- 项目存储：全局项目索引与每项目元数据；限制所有文件操作在项目库内。
- 数据接入：流式复制、文件指纹、CSV/XLSX 解析、原始结构采样及 Parquet 转换。
- 画像引擎：基础统计、缺失、唯一性、重复、类型、相关性和任务就绪度。
- 规则引擎：阈值、证据、风险、置信度、冲突和用户确认记录。
- 流水线：版本化配置、fit/transform 边界、组件能力协议、缓存依赖和数据血缘。
- 任务系统：独立工作进程、单大型任务队列、取消、步骤级检查点及恢复。
- 评估：固定划分和随机种子的快速基线比较。
- 报告与导出：自包含 HTML、CSV/XLSX、ZIP 和安全的复现状态。

## 处理组件能力协议

每个组件至少公开：稳定标识与版本、适用任务、输入输出角色、是否需要 fit、fit 数据边界、是否流式、是否改变行数或列数、稀疏兼容性、资源估计器、风险与泄漏等级、可序列化状态以及取消检查点。

这份协议是规则推荐、执行计划、资源降级、缓存失效、日志记录和脚本导出的共同基础，应先于高级算法实现。

## 数据生命周期

上传文件以 1 MiB 分块流式复制到项目 `source` 目录，同时执行大小限制并计算 SHA-256。CSV 导入先检查编码、表头和常见分隔符，再执行有界抽样画像；不允许静默跳过损坏行。分析与处理使用 `working` 中的 Parquet 和步骤缓存；完成数据进入 `results`；用户生成的可移交文件进入 `exports`。任何删除操作都必须解析并验证绝对路径位于当前项目根目录内。

上传阶段失败且元数据尚未建立时清理本次临时项目；原始文件保存成功后发生的画像错误则保留 `failed` 项目和可恢复错误信息。这样既避免孤立目录，也保留诊断入口。

项目库选择保存在版本化的本地应用设置中，并通过库根目录标记文件识别。首次运行由用户确认路径；切换路径只影响后续读写，不自动迁移、合并或删除旧项目。普通非空目录在没有合法库标记时拒绝接管。

每个画像成功的项目生成版本化 `analysis.json`。该文件保存字段主角色、六维质量评分、扣分证据、规则建议、启停选择与冲突关系；`project.json` 继续作为轻量项目摘要。字段调整会重新构建依赖它的任务就绪度和建议，规则选择在写入前由服务端统一校验，冲突组合不进入后续流水线。

分类与回归的统计处理遵循“先划分、后拟合”：缺失目标记录先隔离，固定随机种子划分训练集与测试集，只有训练集可以产生填充值、类别词表、缩放参数和特征筛选状态。状态以 JSON 保存，工作数据以 Parquet 保存；不使用 Pickle。测试集新类别进入显式 unknown 特征。字段或建议变化会使现有 `pipeline-state.json` 和对应工作文件失效。

快速评估复用同一次划分的原始和处理后工作数据，以逻辑回归或 Ridge 对比最低兼容基线与完整方案。CSV 默认写入 UTF-8 BOM。HTML 报告是无脚本、无外链的自包含文件，动态内容必须转义并用 CSP 禁止外部资源。下载 API 只接受固定工件名称，由服务端映射到项目内路径；上游或流水线变化会使评估与导出一起失效。

纯数据清洗不进入训练/测试划分，也不要求目标列；它在完整去重数据上拟合并转换基础步骤，生成单个 `processed.parquet` 和 `processed.csv`。运行清单使用 `full_rows` 明确表示处理范围，避免把完整数据伪装成训练集。聚类的执行与诊断仍位于 Beta 边界。

## 安全边界

- 服务仅绑定 `127.0.0.1`，启动时生成随机令牌。
- 严格限制 CORS、报告脚本和文件路径。
- 配置文件按版本化 JSON Schema 校验。
- 不使用来自不可信来源的 Pickle；常规状态优先使用 JSON 与 NPZ。
- 日志默认去除字段样例和敏感值。
- 更新检查只读取版本信息，不携带项目数据。
