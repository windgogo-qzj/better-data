# Better Data 系统架构

## 总览

Better Data 采用 Windows 本地优先架构：桌面启动器负责生命周期和系统托盘，浏览器前端负责交互，本地 FastAPI 后端负责文件、项目、任务和数据处理，工作进程负责高成本计算。

```text
Windows 启动器
  ├─ 系统托盘与本地通知
  ├─ 启动 127.0.0.1 本地服务
  └─ 打开默认浏览器
             │
React 工作台 ─┼─ FastAPI API
             │     ├─ 项目服务
             │     ├─ 数据画像与规则引擎
             │     ├─ 流水线编排器
             │     ├─ 任务队列与检查点
             │     └─ 报告与导出
             │
             └─ SQLite 元数据 + Parquet 工作数据 + 原始文件副本
```

## 组件边界

- 前端：八阶段工作流、字段配置、问题证据、流水线编辑、任务进度和导出。
- API：本地令牌校验、输入验证、项目和任务状态接口，不在请求线程执行大计算。
- 项目存储：全局项目索引与每项目元数据；限制所有文件操作在项目库内。
- 数据接入：流式复制、文件指纹、CSV/XLSX 解析、原始结构采样及 Parquet 转换。
- 画像引擎：基础统计、缺失、唯一性、重复、类型、相关性和任务就绪度。
- 规则引擎：阈值、证据、风险、置信度、冲突和用户确认记录。
- 流水线：版本化配置、fit/transform 边界、组件能力协议、缓存依赖和数据血缘。
- 任务系统：独立工作进程、单大型任务队列、取消、步骤级检查点及恢复。
- 评估：固定划分和随机种子的快速基线比较。
- 报告与导出：自包含 HTML、CSV/XLSX、ZIP 和安全的复现状态。

## 处理组件能力协议

每个组件至少公开：稳定标识与版本、适用任务、输入输出角色、是否需要 fit、fit 数据边界、是否流式、是否改变行数或列数、稀疏兼容性、资源估计器、风险与泄漏等级、可序列化状态以及取消检查点。

这份协议是规则推荐、执行计划、资源降级、缓存失效、日志记录和脚本导出的共同基础，应先于高级算法实现。

## 数据生命周期

上传文件以流式方式复制到项目 `source` 目录并计算 SHA-256。分析与处理使用 `working` 中的 Parquet 和步骤缓存；完成数据进入 `results`；用户生成的可移交文件进入 `exports`。任何删除操作都必须解析并验证绝对路径位于当前项目根目录内。

## 安全边界

- 服务仅绑定 `127.0.0.1`，启动时生成随机令牌。
- 严格限制 CORS、报告脚本和文件路径。
- 配置文件按版本化 JSON Schema 校验。
- 不使用来自不可信来源的 Pickle；常规状态优先使用 JSON 与 NPZ。
- 日志默认去除字段样例和敏感值。
- 更新检查只读取版本信息，不携带项目数据。
