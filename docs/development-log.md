## 2026-09-11：CSV 流式导入与基础数据画像

| 项目 | 内容 |
| --- | --- |
| GitHub Issue | [#5 完成 CSV 流式导入与基础数据画像](https://github.com/windgogo-qzj/better-data/issues/5) |
| Pull Request | [#11 完成 CSV 流式导入与基础数据画像](https://github.com/windgogo-qzj/better-data/pull/11) |
| 分支 | `feat/5-csv-import-profile` |
| 核心提交 | `6b32fa0 feat: 完善 CSV 导入与基础画像` |
| 当前阶段 | PR #11 已通过 GitHub Actions 并合并，Issue #5 已关闭 |

### 开发前审计

- 已有 `POST /api/projects`、流式文件写入、SHA-256 和 Polars 抽样画像雏形。
- 自动测试只有一个健康检查，不能证明上传、大小限制、哈希或画像行为正确。
- CSV 使用 `ignore_errors=True`，异常行可能被静默忽略，不符合“错误文件得到明确提示”的验收要求。
- 上传超限时只删除部分文件，会留下没有元数据的空项目目录。
- 返回模型缺少抽样状态和可直接展示的行预览。

### 本次实现

- 文件仍以 1 MiB 分块流式写入，同时计算 SHA-256 并执行大小上限检查。
- CSV 在进入 Polars 前检查 UTF-8/UTF-8 BOM、空文件、空表头和重复表头。
- 自动识别逗号、分号、TAB 和竖线四种常见字段分隔符。
- 关闭 Polars 的静默容错；解析失败返回包含恢复方向的中文错误。
- `DatasetProfile` 增加 `is_sampled` 和最多五行的 `preview_rows`。
- 超过画像上限时只使用前 N 行并返回明确抽样警告。
- 上传阶段失败且尚未生成 `project.json` 时，安全清理本次新建的项目目录。
- 数据画像失败时仍保留原始文件和 `failed` 项目记录，便于用户查看错误并恢复。

### 自动化验证

本地运行 `python -m pytest -q`，结果为 **9 passed**。覆盖：

1. CSV 上传、项目创建和项目列表。
2. 原始文件字节一致性与 SHA-256。
3. 字段数量、缺失值、抽样标记和行预览。
4. 分号分隔符识别。
5. 空文件、空表头、重复表头和非 UTF-8 编码。
6. 不支持的扩展名。
7. 文件超过上限后的错误响应和残留目录清理。

GitHub Actions 在 Windows 环境重新执行前端构建和后端测试，两个任务均通过。Actions 对仍使用 Node.js 20 运行时的第三方 Action 给出弃用提示；项目应用使用的 Node.js 版本仍为 22.13.0，该提示不影响本次验收。

### 关键决策

- **严格解析优先于静默修复**：导入阶段不猜测如何修复损坏行，避免无提示的数据丢失。
- **UTF-8 是 MVP 的明确边界**：其他编码先给出清晰错误，后续可在显式转码功能中安全支持。
- **画像保持有界**：读取 `sample_rows + 1` 行判断是否抽样，不为了精确总行数再次完整扫描大型 CSV。
- **错误项目可诊断**：成功保存原始文件后发生的画像错误保留项目；尚未完成上传的项目不保留。

### 已知限制

- MVP 暂不支持自动转码 GBK 等本地编码。
- 当前画像基于文件前部抽样，不代表全量精确统计。
- CSV 分隔符识别限定为逗号、分号、TAB 和竖线。
- Starlette 测试客户端在当前依赖组合下报告弃用警告，不影响测试结果；依赖升级应单独处理。

## 2026-09-11：项目库与本地项目生命周期

| 项目 | 内容 |

| Pull Request | [#12 建立项目库与本地项目生命周期](https://github.com/windgogo-qzj/better-data/pull/12) |
| 分支 | `feat/1-project-lifecycle` |
| 核心提交 | `fc9552e feat: 实现可配置项目库生命周期` |
| 当前阶段 | PR #12 已通过 GitHub Actions 并合并，Issue #1 已关闭 |

### 开发前审计

- 后端项目库只能通过环境变量或默认路径指定，前端无法查询或修改。
- 首次运行不会要求用户确认数据保存位置。
- 项目库选择没有持久化配置，服务重启后无法恢复用户选择。
- 任意目录一旦被误选都可能被写入，缺少“这是 Better Data 项目库”的身份标记。
- 已有项目列表接口，但没有单项目详情接口。

### 本次实现

- 新增 `GET/PUT /api/settings/project-library`，查询和更新当前项目库。
- 首次运行返回 `needs_setup`，前端自动打开项目库设置，并在工作台持续提示确认。
- 项目库路径写入版本化的 `app-settings.json`，服务重启时自动恢复。
- 项目库写入 `.better-data-library.json` 标记；只接受空文件夹、已有标记的目录或兼容的旧项目库。
- 拒绝相对路径、普通文件和未标记的非空文件夹，避免覆盖无关数据。
- 切换项目库只更新后续读写位置，不移动、不合并、不删除原目录。
- 新增 `GET /api/projects/{project_id}`，并限制项目 ID 为 32 位小写十六进制格式。
- 前端增加首次设置提示、项目库设置对话框、路径错误说明和移动端设置入口。
- 设置保存后重新加载项目列表，界面同步显示新项目库的项目数量和存储占用。

### 自动化验证

本地后端测试为 **15 passed**，新增覆盖：

1. 首次运行的默认项目库和 `needs_setup`。
2. 项目库标记文件及其版本信息。
3. 选择结果写入配置并在 `ProjectStore` 重启后恢复。
4. 新项目写入所选项目库并能通过详情 API 读取。
5. 相对路径、普通非空文件夹和不存在项目的拒绝行为。
6. 切换失败时不修改原文件夹内容。

同时通过 `pnpm lint`、`pnpm build` 与 `git diff --check`。

### 关键决策

- **用户路径必须可识别**：项目库使用标记文件建立身份，避免仅凭目录名称猜测。
- **切换不是迁移**：修改项目库是低风险设置操作；数据迁移、合并和删除需要未来单独流程与确认。
- **配置使用原子替换**：项目元数据、库标记和全局设置都先写临时文件再替换，降低中断导致半写入的风险。
- **保留旧库兼容性**：已有包含合法 `project.json` 的默认库可以补写标记，不阻断早期版本数据。

### 已知限制

- 浏览器不能提供稳定、跨浏览器的原生目录选择能力，MVP 使用绝对路径输入；Windows 启动器阶段再接入系统文件夹选择器。
- 切换项目库后不会在界面中同时聚合多个库。
- 当前没有项目删除、回收站或迁移功能，这些属于后续生命周期能力。

## 2026-09-11：字段确认、质量评分与规则建议

| 项目 | 内容 |
| --- | --- |
| GitHub Issue | [#8 实现字段确认、质量评分与规则建议](https://github.com/windgogo-qzj/better-data/issues/8) |
| Pull Request | [#13 实现字段确认、质量评分与规则建议](https://github.com/windgogo-qzj/better-data/pull/13) |
| 分支 | `feat/8-field-quality-rules` |
| 后端提交 | `9a59c52 feat: 建立字段质量分析领域模型` |
| 前端提交 | `eb53bd7 feat: 新增字段与质量确认工作台` |
| 当前阶段 | PR #13 已通过 GitHub Actions 并合并，Issue #8 已关闭 |

### 开发前审计

- 项目画像只有字段类型、缺失数和唯一值数，没有用户可保存的字段角色。
- 质量信息只是离散统计，没有六个维度、综合分或可追溯扣分证据。
- 处理建议没有领域模型、稳定规则编号、风险、置信度、证据、替代方案和启停状态。
- 前端项目列表没有进入项目分析详情的入口。
- 服务端没有建议冲突检查，无法保证互斥操作不会静默进入后续流水线。

### 本次实现

- 新增 12 种字段角色：连续数值、离散数值、名义类别、有序类别、布尔、日期时间、ID、文本、目标、分组、敏感和忽略。
- 根据抽样类型、唯一率、字段名和示例长度生成初始角色；推断始终允许用户修正。
- 新增完整性、有效性、一致性、唯一性、结构可用性和任务就绪度六维评分。
- 每个维度保留稳定扣分规则编号、扣分原因、字段和抽样证据；综合分为六维等权启发式平均。
- 新增规则建议模型，包含稳定 ID、规则编号、问题、证据、严重度、风险、置信度、动作参数、预计影响、副作用、替代方案和冲突列表。
- 低风险常量移除、ID 排除和缺失指示可默认开启；高风险移除和目标列配置默认关闭。
- 同字段“移除列”和“添加缺失指示”等互斥操作在服务端保存时返回 HTTP 409，要求用户先解决冲突。
- 字段配置必须精确覆盖原始结构；监督学习必须且只能有一个目标列，清洗与聚类预处理不得设置目标列。
- 分析结果写入项目内版本化 `analysis.json`，字段和建议选择可在重启后恢复。
- 新增项目分析工作台，展示项目进度、抽样声明、六维分数、扣分证据、字段角色编辑及建议启停。
- 项目列表名称改为可访问的详情链接；项目页在小屏使用横向可滚动表格，在 640/1024px 逐级扩展评分和步骤布局。

### API 变化

- `GET /api/projects/{project_id}/analysis`：读取或为旧项目补建分析。
- `PUT /api/projects/{project_id}/fields`：保存完整字段角色并重新计算评分和建议。
- `PUT /api/projects/{project_id}/recommendations`：保存启用建议，并执行未知 ID、重复项和冲突检查。

### 自动化验证

本地后端测试为 **19 passed**，新增覆盖：

1. ID 等字段角色推断。
2. 六维评分结构及抽样标记。
3. 建议规则编号、置信度、证据和默认启停状态。
4. 字段结构完整性与监督学习唯一目标列约束。
5. 字段确认后目标列建议消失并重新计算任务就绪度。
6. 冲突建议返回 HTTP 409。
7. 建议启停保存和重新读取。
8. 不存在项目返回 HTTP 404。

前端通过 `pnpm lint` 和 `pnpm build`，生产构建识别首页和动态项目页两条路由；同时通过 `git diff --check`。

### 关键决策

- **分析与项目摘要分离**：`project.json` 保持轻量列表信息，字段和规则详情进入独立 `analysis.json`。
- **评分是解释入口，不是结论**：始终展示分项和扣分证据，并在抽样时明确提示局限。
- **推断不等于确认**：系统不会自动猜测监督学习目标，必须由用户明确选择。
- **选择在服务端复核**：前端允许自由组合，保存时由服务端以稳定 ID 验证，避免绕过 UI 后产生静默冲突。
- **本阶段只形成方案**：建议保存不会修改数据，为下一阶段安全流水线提供可审计输入。

### 已知限制

- 当前评分基于有界抽样，尚不包含全量重复行、相关性、异常值和业务规则扫描。
- 有效性与一致性只能使用现有画像信号；类型解析候选和类别规范化证据将在流水线阶段增强。
- 字段角色为单一主角色；敏感性与分组等复合标签将在后续数据治理模型中评估。
- 前端尚未提供规则阈值编辑，MVP 先使用需求文档中的冻结默认值。

## 2026-09-11：分类与回归安全预处理流水线

| 项目 | 内容 |
| --- | --- |
| GitHub Issue | [#2 实现分类与回归安全预处理流水线](https://github.com/windgogo-qzj/better-data/issues/2) |
| Pull Request | [#14 实现分类与回归安全预处理流水线](https://github.com/windgogo-qzj/better-data/pull/14) |
| 分支 | `feat/2-safe-preprocessing` |
| 后端提交 | `6a12744 feat: 实现防泄漏预处理流水线` |
| 前端提交 | `45d76be feat: 接入安全预处理配置与执行` |
| 支撑提交 | `b454b72 feat: 持久化可复用的原始数据划分` |
| 当前阶段 | PR #14 已通过 GitHub Actions 并合并，Issue #2 已关闭 |

### 开发前审计

- 已有字段角色和建议选择，但没有任何数据变换执行路径。
- 项目没有训练集/测试集工作文件、可复现流水线配置或已学习参数记录。
- 没有自动测试能证明测试数据不会参与填充、编码、缩放和特征筛选参数学习。
- 上游字段或建议变化不会使旧处理结果失效，存在结果与配置不一致风险。

### 本次实现

- 新增版本化 `PipelineConfig`，支持 10%～50% 测试集比例、固定随机种子、分类分层、完全重复行处理、训练集常量筛选、均值/中位数填充、众数/缺失类别填充、标准/Min-Max/关闭缩放及类别维度上限。
- 数据先移除缺失目标记录和可选完全重复行，再执行固定种子的训练/测试划分。
- 数值填充值、缩放中心与尺度只从训练集计算；测试集仅应用训练集状态。
- 类别填充值、类别词表和高基数截断只从训练集生成；测试集未见类别进入显式 `__unknown` 特征。
- 常量特征只依据训练集判断，避免测试分布改变特征选择。
- 已启用的移除、排除和缺失指示建议真正进入执行计划；运行记录保存其稳定建议 ID。
- 目标缺失记录单独写入，不填充目标列；回归目标在划分前执行严格数值校验。
- 处理后的训练/测试数据、同一划分的原始基线数据和目标缺失数据以 Parquet 原子替换写入 `working/`，原始文件不修改。
- 保存输入 SHA-256、完整配置、学习参数、特征结构、未知类别计数、文件哈希和行列数到 `pipeline-state.json`。
- 字段角色或建议选择变化会删除依赖它们的流水线状态与工作文件，并将项目恢复为待处理状态。
- 项目分析页增加流水线配置、未保存配置阻断、防泄漏说明、运行状态和内部结果摘要。

### API 变化

- `POST /api/projects/{project_id}/pipeline-runs`：按提交配置同步执行一次安全预处理。
- `GET /api/projects/{project_id}/pipeline-runs/latest`：读取最近一次运行清单；尚未运行返回 404。

### 自动化验证

本地后端测试为 **23 passed**，新增覆盖：

1. 分类任务固定种子分层 80/20 划分。
2. 训练集均值与全量均值不同，证明测试集没有参与填充值学习。
3. 测试集独有类别映射到 `segment__unknown`，不进入训练类别词表。
4. 缺失目标记录单独写入 `target-missing.parquet`。
5. 相同配置与随机种子生成相同学习参数及结果文件哈希。
6. 未确认字段时拒绝执行。
7. 字段变化后旧运行记录和工作文件失效。
8. 回归任务严格验证数值目标且不执行分层划分。

前端通过 `pnpm lint` 和 `pnpm build`，并通过 `git diff --check`。

### 关键决策

- **先划分、后拟合**：除不依赖统计学习的完全重复行处理外，所有可学习状态都严格限制在训练集。
- **不用 Pickle 保存状态**：MVP 将学习参数保存为可审计 JSON，将数据保存为 Parquet，降低不可信反序列化风险。
- **未知类别显式化**：One-Hot 总是提供 unknown 列，避免测试集或未来数据的新类别被误解为某个已知类别。
- **上游变化立即失效**：字段和建议属于流水线上游，保存变化时删除派生工作文件，避免陈旧结果被继续评估。
- **内部结果与正式导出分层**：本任务只生成项目内部工作数据；CSV、HTML 报告和模型对比由 Issue #3 统一生成。

### 已知限制

- 当前执行仍在 API 请求内同步完成，后台任务、取消和步骤恢复属于 Beta。
- MVP 全量处理使用内存中的 Polars DataFrame；超大文件资源估计、分块和降级策略属于 v1.0 性能里程碑。
- 当前仅执行 CSV 分类与回归；XLSX 全量处理和聚类预处理在 Beta 路线图中。
- MVP 特征选择只有常量字段和已确认规则排除，高相关与互信息筛选尚未实现。

### 本次实现

- 流水线额外持久化同一次划分的 `train-raw.parquet` 和 `test-raw.parquet`，作为公平基线输入。
- 最低限度兼容方案只做训练集生成的数值中位数填充、类别众数填充和 One-Hot；完整方案直接读取用户确认的处理结果。
- 分类使用逻辑回归，输出准确率、平衡准确率和加权 F1。
- 回归使用 Ridge，输出 MAE、RMSE 和 R²。
- 评估前逐项验证原始与处理后训练/测试行数、目标值及顺序一致；不一致时停止，而不是给出不可比指标。
- 支持“快速”和“关闭”两档；关闭时不训练模型，但仍生成数据、报告和运行记录。
- 训练集和测试集导出为带 UTF-8 BOM 的 CSV，便于 Excel 和常用分析工具直接打开。
- 生成单文件离线 HTML 报告，内嵌样式、不含脚本和外部链接，并通过 CSP 禁止任何外部资源加载。
- 项目名称、文件名和其他动态文本全部 HTML 转义，避免报告注入。
- `evaluation.json` 保存输入哈希、任务、随机种子、同划分声明、两组指标和导出文件哈希。
- 下载接口只接受 `train-csv`、`test-csv`、`report` 三个固定名称，不接收客户端文件路径。
- 新流水线运行或任何上游字段/建议变化都会删除旧评估、报告和 CSV，避免结果错配。
- 项目页增加评估档位、同划分保证、双方案指标卡和三个下载入口。

### API 变化

- `POST /api/projects/{project_id}/evaluation`：执行快速评估或仅生成导出。
- `GET /api/projects/{project_id}/evaluation`：读取最近一次评估与导出清单。
- `GET /api/projects/{project_id}/artifacts/{artifact_name}`：从固定白名单下载 CSV 或 HTML。

本地后端测试为 **27 passed**，新增覆盖：

1. 分类前后方案使用同一行数、随机种子和目标顺序。
2. 逻辑回归输出三项分类指标。
3. Ridge 输出 MAE、RMSE 和 R²。
4. 训练和测试 CSV 均以 UTF-8 BOM 开头。
5. HTML 报告包含离线 CSP、不含 HTTP(S) 外链，并正确转义模拟脚本项目名。
6. 报告 SHA-256 与实际文件一致。
7. 下载白名单允许三个结果文件并拒绝未知工件。
8. 评估关闭时不产生模型指标但仍生成导出。
9. 新流水线运行使旧评估结果失效。

前端通过 `pnpm lint`、`pnpm build` 与 `git diff --check`。

### 关键决策

- **公平性优先**：评估复用流水线保存的原始与处理后同一划分，而不是依赖“相同种子大概相同”的重新划分。
- **基线只求最低兼容**：基线只解决模型无法读取缺失和类别的问题，不加入完整方案中的缩放、建议操作和高级状态。
- **离线报告默认零网络能力**：报告不使用 CDN、远程字体或脚本，CSP 进一步限制意外外联。
- **下载使用逻辑名称**：客户端永远不能提交本机路径，服务端把有限逻辑名称映射到项目内已知文件。
- **结果记录不自我哈希**：`evaluation.json` 记录可交付 CSV 与报告哈希，避免文件把自身哈希写入自身导致循环不一致。

### 已知限制

- 快速指标只用于对比预处理前后基线，不代表最终模型选择或业务效果。
- 当前不包含交叉验证、置信区间、阈值曲线和模型调参。
- CSV 默认导出，XLSX 和完整 ZIP 结果包属于 Beta。
- 报告不提供 PDF，符合已冻结的交互式 HTML 优先范围。

### 问题复核

- 首页首屏与流程区可同时出现在视口中，产品介绍缺少独立完整页面感。
- 流程操作台与页面共用滚轮事件，用户在切换步骤时可能同时移动页面。
- 五个阶段使用高度相似的抽象图片，无法说明每一步的真实任务。
- 项目回收或恢复后前端继续使用局部旧状态，列表与后端目录可能短暂不一致。
- 第二次导入本地常见编码 CSV 时可能失败，并在项目库中留下不可继续的项目。

### 本次实现

- 首页首屏使用数据工作人员面对混乱数据的专属图片，产品定位与品牌信息合并呈现。
- 产品介绍与产品流程按完整视口切换；流程操作台拦截自身滚轮，操作台之外保持页面滚动。
- 五个阶段分别展示问题记录、证据链、规则确认、训练测试边界和交付文件。
- 工作台与项目页的 Better Data 品牌入口统一返回首页。
- 回收、恢复与永久删除后重新读取服务端项目库，不依赖乐观状态猜测结果。
- CSV 解码依次尝试 UTF-8、UTF-8 BOM、GB18030 和 Windows-1252；上传早期失败时清理临时目录。
- 将 `backend/work/` 纳入忽略规则，防止本地项目数据进入版本控制。

### 验证

- `pnpm lint` 和 `pnpm build` 通过。
- 后端自动化测试：**33 passed**。
- GitHub Actions 的前端和后端任务均通过。
- 浏览器检查首页完整切屏、五阶段切换、品牌返回首页和第二次导入恢复路径。

### 关键决策与限制

- 产品流程用实际任务差异表达阶段，不使用同一张装饰图反复变体。
- 状态变更后以后端目录为事实来源，避免前端列表与磁盘状态分叉。
- 编码回退只覆盖当前验证过的常见本地导出编码；无法可靠识别的输入仍明确拒绝。
- 用户项目和本机路径不进入测试、截图或提交历史。

### 根因

- 删除菜单关闭时会卸载当前项目，确认对话框随后读取到空值，导致标题出现 `undefined`，请求也失去项目 ID。
- Windows 安全软件或文件索引可能短暂占用项目目录，单次 `Path.replace` 会直接失败。
- 浏览器平滑滚动与页面自定义切屏同时计算相对位置，可能停在两个区块之间。

### 修复

- 打开确认对话框前保存不可变的项目快照，使菜单生命周期不再影响删除目标。
- 项目目录移动优先使用原子替换，遇到 `PermissionError` 时使用同卷 `shutil.move` 回退；目标冲突仍拒绝覆盖。
- 切屏按目标元素的绝对文档位置计算，并在过渡期间节流重复滚轮事件。
- 增加 Windows 移动回退测试，覆盖回收、恢复和冲突保护。

### 验证

- 前端 ESLint 与生产构建通过。
- 后端自动化测试：**34 passed**。
- 实际项目生命周期验证：项目库 5 / 回收站 0，移除后 4 / 1，恢复后 5 / 0。
- 首页从产品介绍向下滚动后流程区顶部误差小于 1 像素；流程操作台滚动时页面位置保持不变。
- GitHub Actions 的前端和后端任务均通过。
